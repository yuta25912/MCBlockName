# MCBlockName
マイクラのブロックの日本語名をjsonで書いていくリポジトリ

ブロックIDごとに、Java版の日本語名とその読み（ひらがな）をまとめています。
ゲームの言語ファイルには読みが入っていないので、「しんそうがん」のようにひらがなでブロックを探したいときに使えます。

## ファイル

| ファイル | 中身 |
|---|---|
| `blocks.json` | ブロックの日本語名と読み |
| `version.json` | `blocks.json` の版と更新日（自動で更新） |
| `mc-versions.json` | 調べたマイクラのバージョンの一覧 |
| `block-versions.json` | ブロックごとの、追加されたバージョン・なくなったバージョン |
| `versions/<バージョン>.json` | そのバージョンにあるブロックIDの一覧 |

## blocks.json の形式

```json
{
  "formatVersion": 2,
  "blocks": {
    "minecraft:birch_planks": {
      "name": "シラカバの板材",
      "yomi": "しらかばのいたざい"
    },
    "minecraft:dirt_path": {
      "name": "土の道",
      "yomi": "つちのみち",
      "aliases": ["草の道", "くさのみち"]
    }
  }
}
```

### 全体

| 項目 | 必須 | 説明 |
|---|---|---|
| `formatVersion` | ○ | JSONの形（項目名やルール）の版。形を変えたときだけ上げる。今は `2`（`1` から `yomi` が必須でなくなった） |
| `blocks` | ○ | ブロックIDをキーにしたオブジェクト |

### ブロックごと

| 項目 | 必須 | 説明 |
|---|---|---|
| キー | ○ | 名前空間付きのブロックID（例: `minecraft:sand`） |
| `name` | ○ | Java版の公式日本語名。最新版での名前を書く |
| `yomi` | – | `name` の読み。分からなければ書かなくてよい（あとで誰かが足す） |
| `aliases` | – | 別の呼び方（旧名、統合版での名前、俗称など）の配列 |

## version.json

```json
{
  "version": 12,
  "updated": "2026-10-11"
}
```

`blocks.json` が `main` に入るたびに、GitHub Actions が `version` を1つ上げて `updated` をその日の日付にします。
手で書き換える必要はありません。
使う側は、小さい `version.json` だけを読んで、`blocks.json` が新しくなったかを確かめられます。

## 対応バージョンのファイル

Java版 1.13〜最新のリリースそれぞれについて、ゲームのデータ生成（`--reports`）で取り出したブロックの一覧です。
1.12 以前はブロックIDの仕組みが違う（数字のID）ので入れていません。
手で書き換えるものではなく、新しいバージョンが出たときにまとめて作り直します。

### mc-versions.json

調べたバージョンの一覧です（古い順）。

```json
{
  "formatVersion": 1,
  "versions": ["1.13", "1.13.1", "...", "26.3"]
}
```

### block-versions.json

```json
{
  "formatVersion": 1,
  "blocks": {
    "minecraft:dirt_path": { "since": "1.17", "item": true },
    "minecraft:grass_path": { "since": "1.13", "until": "1.16.5", "item": true }
  }
}
```

| 項目 | 説明 |
|---|---|
| `since` | そのブロックが最初にあったバージョン。`1.13` は「1.13 にはもうあった」という意味 |
| `until` | 最後にあったバージョン。今もあるブロックには書かない（名前が変わってなくなったものなど） |
| `item` | アイテムとして存在するか。植木鉢に植えた花や壁掛けの看板などは `false` |

### versions/&lt;バージョン&gt;.json

そのバージョンにあるブロックIDの一覧です。自分のバージョンのファイルだけを読めば済みます。

```json
{
  "version": "1.20.1",
  "blocks": ["minecraft:acacia_button", "minecraft:acacia_door", "..."]
}
```

## 書き方のルール

- **キー**は小文字の名前空間付きID。`minecraft:` も省略しない。
- **並び順**はキーのアルファベット順。ずれていても、`main` に入ったあとで自動で並べ替えられます。
- **`name`** はゲームの言語設定を日本語にしたときに表示される名前をそのまま書く。
- **`yomi`** はひらがなと長音「ー」だけで書く。カタカナの部分もひらがなにする。読みが分からないときは `yomi` ごと書かずに追加してよい。
  - ○ `だいやもんどぶろっく`
  - × `ダイヤモンドぶろっく`、`だいやもんど ぶろっく`
- **`aliases`** は文字の種類が自由。漢字の別名を入れるときは、その読みも並べて入れる（例: `["草の道", "くさのみち"]`）。
- 他のModのブロックも、そのModの名前空間で追加してよい（例: `create:andesite_casing`）。
- インデントはスペース2つ、ファイルの文字コードはUTF-8。

## バージョンの違いについて

名前（`blocks.json`）はバージョンごとに分けず、1つのファイルに全バージョンのブロックを入れます。
古いバージョンにないブロックが入っていても、使う側でそのIDを無視すれば済むためです。
名前が変わったブロックは、`name` に最新版の名前を書き、古い名前を `aliases` に入れてください。

どのバージョンにどのブロックがあるかは、名前とは別に「対応バージョンのファイル」（`block-versions.json` と `versions/`）にまとめています。
自分のバージョンにあるブロックだけを使いたいときは、こちらと組み合わせてください。

## 追加・修正のしかた

1. このリポジトリをフォークする
2. `blocks.json` にブロックを追加する（なるべくアルファベット順の位置に入れる）
3. Pull Request を出す

Pull Request を出すと、GitHub Actions が `blocks.json` の中身を自動でチェックします。
読みにひらがな以外が入っている、同じキーが2回ある、などのときはエラーになるので、直してからもう一度 push してください。
`version.json` は触らなくて大丈夫です。

## 自由に使ってください

`blocks.json` は誰でも自由に使えます。

- Mod、プラグイン、ツール、Webサイトなど、何に使ってもかまいません。商用でも大丈夫です。
- 中身を書き換えたり、一部だけ抜き出したりしてもかまいません。
- 連絡やクレジット表記はいりません（書いてもらえるとうれしいです）。
